A data analytics project built for **Atlantic Recording Corporation** as part of the **Unified Mentor Data Analytics Program**.
It studies 27,800 daily snapshots of the US Top 50 playlist to understand how stable the chart is, how long songs stay relevant,
which artists dominate, and how song attributes (duration, explicit content, album type, album size) relate to chart success.

> This is **historical analytics**: it describes what happened. It does not predict rankings or recommend songs.

## Features

**Interactive Streamlit dashboard** with sidebar filters (date range, rank range, album type, explicit/clean, artist, song, and a reset button) and seven tabs:

| Tab | What it shows |
|---|---|
| 📅 Timeline Explorer | Full Top 50 for any day, daily popularity trend, rank heatmap of the longest-charting songs |
| 📈 Song Trends | Rank and popularity-trend lines, longest-charting songs, peak rank vs longevity |
| 🏆 Artist Leaderboard | Artist Dominance Index, unique songs, days present, dominance over time |
| 🔬 Popularity vs Rank | Correlations, popularity by rank tier, popularity stability vs chart volatility |
| 🔞 Content Attributes | Explicit vs clean, single vs album, duration bands, album size |
| 🔁 Movement | Rank-change distribution, entries and exits, fast risers, steady climbers, decliners |
| 🧪 Data Quality | Validation report and a download button for the filtered data |

**Batch reporting** (`run_eda.py`) exports result tables and generates a research paper and executive summary with the numbers computed from the data.

**Robust by design:** the dashboard handles tiny or empty filter selections, missing or malformed data files, different date formats and encodings, and dirty rows.

## Usage

Run the following from the folder that contains `app.py`:

```bash
python run_eda.py                 # writes tables, research paper and executive summary to outputs/
python -m streamlit run app.py    # launches the dashboard at http://localhost:8501
```

Using `python -m streamlit` guarantees Streamlit runs inside the same environment where you installed the packages.

### Dashboard filters

| Filter | Input |
|---|---|
| Date range | Pick a start **and** end date |
| Rank range | Drag both ends of the slider (1–10 = Top 10 only) |
| Album type | `album`, `single`, `compilation` |
| Content | All / Explicit only / Non-explicit only |
| Artist / Song | Pick one or more, or leave empty for all |
| 🔄 Reset all filters | Restores every filter to its default |

All filters combine, so each one you add narrows the data further. Very small selections (a single song or day) can leave some charts sparse, which is expected.

## Dataset

`data/Atlantic_United_States.csv`: daily US Top 50 playlist snapshots.

| Column | Description |
|---|---|
| `date` | Snapshot date (`dd-mm-yyyy`) |
| `position` | Playlist rank (1–50) |
| `song` | Song title |
| `artist` | Artist(s) |
| `popularity` | Popularity score from the Atlantic API |
| `duration_ms` | Duration in milliseconds |
| `album_type` | single / album / compilation |
| `total_tracks` | Number of tracks in the album |
| `is_explicit` | Explicit content flag |
| `album_cover_url` | Album artwork URL |

**Coverage:** 27,800 rows, 18 May 2024 to 27 Nov 2025, 555 snapshot days, 977 unique songs, 244 lead artists.

## Methodology and KPIs

**Validation:** rank range 1–50, missing values, duplicate song-day rows (48 removed, best rank kept), missing calendar days (4), artist name standardisation. Songs are identified by *title + artist*.

| KPI | Definition |
|---|---|
| Days on Chart | Number of days a song appears (longevity) |
| Average Rank | Mean daily position |
| Best Rank | Highest position reached |
| Rank Volatility Index | Standard deviation of a song's daily rank |
| Popularity Trend Score | 7-day rolling mean of popularity |
| Artist Dominance Index | Artist's share (%) of all rank points, where points = 51 − position |
| Explicit Content Share | Share of chart rows flagged explicit |

**Statistics:** Spearman and Pearson correlations, Mann-Whitney U tests. Tests are run at the **song level** (each song counts once) because daily rows of the same song are not independent.

## Key findings

- **A calm chart.** Only about 3.5 of the 50 slots change on an average day (about 7% turnover), and 31.9% of day-to-day moves are "no change".
- **Most songs are short-lived.** The median song stays 7 days; 157 of 977 songs appear once. Yet 35 songs lasted 180+ days.
- **Singles last longer, but do not peak higher.** Median 13 vs 6 days on chart and popularity 84.7 vs 78.0 (both p < 0.001), while best rank shows no significant difference (p = 0.21).
- **Concentrated artist share.** The top 5 artists hold 27.0% of all rank points and the top 10 hold 41.1%. Taylor Swift leads through breadth (96 songs); Sabrina Carpenter through depth (14 songs, average rank 17.6).
- **Popularity is only loosely tied to rank** (Spearman ρ = −0.25).
- **Explicit content and song length** show small, inconsistent effects. Album tracks from very large projects (21–40 songs) fare worst.

The full write-up is in the research paper (`outputs/research_paper.md`, plus the Word version).

## Limitations

- Descriptive and correlational only; no causal claims.
- Row-level averages favour long-running songs, so song-level results are reported alongside.
- `album_type` changes between days for 33 songs and `is_explicit` for 12; each song's most common value is used.
- The 4 missing calendar days can make a few songs look as if they left and re-entered the chart.
- Lead artist is the first name in a collaboration credit (a simple rule).
- Some dates in the source file do not line up with real-world release timing; dates are used exactly as given.
- Single market, single playlist.
